Add the `read_member` MCP tool that reads individual method/field source by FQN, including Javadoc, annotations, and body.

Purpose: Users get FQNs from `list_members` or `search_symbols` output. Currently they must `read_source` for the entire class and manually find the member. `read_member` lets them jump directly to the relevant member source.

Output: `src/browsing/member-extractor.ts` (domain logic), `src/tools/read-member.ts` (MCP tool), tests for both, tool registration and description.

  <action>
    Create `src/browsing/member-extractor.ts` with three exported functions:

    1. `parseMemberFqn(fqn: string): ParsedFqn | null`
       - Interface: `{ className: string; memberName: string; isMethod: boolean; isField: boolean }`
       - Split on first `#`. If no `#`, return null.
       - If suffix after `#` ends with `()`, strip it, set isMethod=true.
       - If suffix after `#` ends with `:`, strip it, set isField=true.
       - Otherwise return null (malformed -- no type indicator).
       - For inner class FQNs like `Outer$Inner#field:`, the className is `Outer$Inner` ($ stays in className).

    2. `findDecorationsStart(lines: string[], rangeStartIdx: number): number`
       - rangeStartIdx is 0-based index into lines array.
       - Scan backward from `rangeStartIdx - 1`.
       - Skip blank lines (lines where `.trim() === ''`).
       - If the line at current position has `.trim()` ending with `*/`, scan upward until finding a line where `.trimStart().startsWith('/**')`. Return that index.
       - If no Javadoc found, return rangeStartIdx.

    3. `extractMemberSource(sourceText: string, enrichedSymbols: EnrichedSymbol[], targetFqn: string): MemberExtraction[]`
       - Interface `MemberExtraction`: `{ source: string; startLine: number; endLine: number; lineCount: number; memberFqn: string; kind: string }`
       - Parse targetFqn via parseMemberFqn to get className and member identity.
       - Split sourceText into lines array.
       - Collect matching symbols: walk enrichedSymbols tree recursively. For inner class FQNs (className contains `$`), navigate into children of the class symbol whose name matches the inner class chain. Match members where `memberFqn` property equals targetFqn.
       - For each matching symbol: use `range.start.line` (1-based) and `range.end.line` (1-based) from the TransformedSymbol. Call `findDecorationsStart(lines, range.start.line - 1)` to find Javadoc start (convert to 0-based for array indexing). Extract `lines.slice(decorationStart, range.end.line)`. Join with `\n`.
       - Return array of MemberExtraction objects (one per match -- multiple for overloads).

    Create `tests/browsing/member-extractor.test.ts`:
    - Test parseMemberFqn with method, field, constructor, inner class, malformed inputs.
    - Test findDecorationsStart with Javadoc present, no Javadoc, blank lines between, annotation-only (should return rangeStartIdx since JDT LS range includes annotations).
    - Test extractMemberSource with mock enriched symbols and source text -- method with Javadoc, field without Javadoc, overloaded methods (two symbols with same FQN), inner class member.
    - Use inline source text fixtures (multi-line template strings) rather than external files.
