<objective>
Close Phase 39 VERIFICATION Failure 1.

**Original hypothesis (wrong):** `withLspDocument` race — `textDocument/definition` fires immediately after `textDocument/didOpen` before JDT LS validates the AST, so on Windows the navigation request returns null/empty. This hypothesis came from the JDT LS internal log timing in the matrix-row.ts diagnostic run, and was disproved by adding 15-second sleeps + documentSymbol synchronization with no effect on the final envelope's `total: 0` outcome.

**Actual root cause (proven by `find-def-DIAG` logging in find-definition.ts):** JDT LS DOES return a valid `Location` for `find_definition` on Windows. The result is silently dropped by `processNavigationLocations` because `uri-mapper.ts`'s `prefixMatches` returns null for the JDT LS-emitted URI.

JDT LS canonicalizes Windows 8.3 short filenames to their long form via `GetLongPathNameW` internally and emits Location.uri values using the LONG form. Example:
- We send: `file:///C:/Users/LOGAND%7E1/AppData/Local/Temp/mcp-jdtls-.../template/TEMPLATE_PACKAGE/TEMPLATE_CLASSNAME.java` (URL-encoded short name from `pathToFileURL`)
- JDT LS returns: `file:///C:/Users/LoganDark/AppData/Local/Temp/mcp-jdtls-.../template--minecraft/net/minecraft/resources/Identifier.java` (long name, no `%7E`)

`prefixMatches` is byte-exact + Windows drive-letter case-fold only (per Phase 36 D-10 "no symlink-resolving API or canonical-path probe"). It does NOT normalize 8.3 short↔long names. JDT LS's long-name URI fails the prefix check against our short-name-derived prefix → `fromFileUri` returns null → `processNavigationLocations` drops the result → final envelope has 0 results despite JDT LS having found the symbol.

**Fix:** In `createUriMapper`, normalize `tempDir` via `realpathSync.native(tempDir)` before constructing `baseUri` / `prefix`. `.native` is the only Node API that resolves Windows 8.3 short names (`realpathSync` without `.native` only resolves symlinks). On Unix the call is a no-op canonicalization (no 8.3 short names exist). Wrap in try/catch with fallback to as-given `tempDir` to keep synthetic test paths working.

Purpose: deliver UNIX-03's "Windows works end-to-end" promise. The matrix-runner.ts evidence in 39-VERIFICATION.md showed Java discovery + cross-jar navigation work at the JDT LS layer; this fix unblocks the same path through the production stdio MCP server.

Output: One source file modified (`src/jdtls/uri-mapper.ts`, ~25 added lines including the explanatory comment), one test file extended (`tests/jdtls/uri-mapper.test.ts`, ~50 added lines for the platform-gated 8.3 test). The seven JDT LS-backed tools (`find_definition`, `find_implementations`, `find_references`, `get_symbol_info`, `list_members`, `read_member`, `type_hierarchy`) all benefit transparently — `processNavigationLocations` is the shared filter that was dropping results across all of them.

```typescript
// =========================================================================
// Windows 8.3 short-name canonicalization (Phase 39 Failure 1 root cause)
// =========================================================================
// JDT LS internally canonicalizes 8.3 short Windows filenames (LOGAND~1)
// to their long form (LoganDark) and emits Location.uri values using the
// long form. The mapper MUST resolve the input tempDir via
// realpathSync.native so its prefix matches JDT LS's reply shape. Without
// this, on a Windows host where os.tmpdir() returns a short-name path,
// find_definition reports a JDT LS reply count of 1 but the envelope's
// final result list is empty (the URI cannot map back to a jar ID).
//
// Only runs on a real Windows host: 8.3 short names are a Windows
// filesystem feature; on Unix realpathSync.native(t) is a no-op
// canonicalization and there's nothing to assert.
describe.runIf(process.platform === 'win32')('Windows: 8.3 short-name canonicalization', () => {
    it('toFileUri + prefix use the canonical (long-name) form when tempDir is an 8.3 short path', async () => {
        const { realpathSync, mkdirSync, rmSync } = await import('node:fs');
        const { tmpdir } = await import('node:os');
        const { join } = await import('node:path');
        const { randomUUID } = await import('node:crypto');

        const shortDir = join(tmpdir(), 'uri-mapper-83-test-' + randomUUID());
        mkdirSync(shortDir, { recursive: true });
        try {
            const longDir = realpathSync.native(shortDir);
            const wasShort = shortDir !== longDir;

            const { createUriMapper } = await import('../../src/jdtls/uri-mapper.js');
            const mapper = createUriMapper(shortDir, new Map([['minecraft', 'minecraft']]));

            const uri = mapper.toFileUri('minecraft', 'foo/Bar.java');
            const longUriPattern = longDir.replace(/\\/g, '/');
            expect(uri).toContain(longUriPattern);

            if (wasShort) {
                expect(uri).not.toContain(shortDir.replace(/\\/g, '/'));
            }

            const longUri = `file:///${longDir.replace(/\\/g, '/')}/minecraft/foo/Bar.java`;
            expect(mapper.fromFileUri(longUri)).toEqual({ jar: 'minecraft', entryPath: 'foo/Bar.java' });
        } finally {
            try { rmSync(shortDir, { recursive: true, force: true }); } catch {}
        }
    });
});
```
