Create `src/tools/type-hierarchy.ts` implementing `registerTypeHierarchyTool(server: McpServer)`:

**Input schema:**
- `class`: z.string() -- FQN (e.g., `net.minecraft.client.MinecraftClient`)
- `jar`: z.string().optional() -- jar ID to find the class in
- `project`: z.string().optional()
- `depth`: z.number().int().min(0).max(10).default(1).optional().describe('Maximum depth for subtype traversal (default: 1, direct subtypes only)')

**Flow -- does NOT use cascading regex (no `patterns`), does NOT need resolveSymbolPosition:**
1. Resolve project, check JDT LS (standard boilerplate)
2. Convert FQN to entry path (same pattern: last dot splits package/class)
3. Find the class source text: if jar specified use that jar, otherwise search all filtered jars by priority. Only need to find the file, not do cascading regex.
4. Build file URI via uriMapper.toFileUri()
5. didOpen with source text
6. Locate the class declaration position: search for `class {SimpleName}` or `interface {SimpleName}` or `enum {SimpleName}` or `record {SimpleName}` in source text using a regex. Extract line/character (0-based) from the source text for the position of the class name. If not found, use line 0 character 0 as fallback.
7. Call `endpoint.send('textDocument/prepareTypeHierarchy', { textDocument: { uri: fileUri }, position })` -- returns TypeHierarchyItem[] or null
8. If null/empty: didClose, return `makeSuccess({ class: className, extends: [], implements: [], subtypes: [] })`
9. Take the first item (the target class itself)

**Walk supertypes to root:**
```typescript
const extendsChain: HierarchyEntry[] = [];
const implementsList: HierarchyEntry[] = [];
let current = item;
while (true) {
  const supers = await endpoint.send('typeHierarchy/supertypes', { item: current });
  if (!supers || supers.length === 0) break;
  for (const s of supers) {
    const entry = toHierarchyEntry(s, loadedProject, uriMapper);
    // SymbolKind 11 = Interface
    if (s.kind === 11) {
      implementsList.push(entry);
    } else {
      extendsChain.push(entry);
    }
  }
  // Continue walking up from the first superclass (class inheritance is single)
  const superclass = supers.find((s: any) => s.kind !== 11);
  if (!superclass) break;
  current = superclass;
}
```

**Walk subtypes (BFS to depth):**
```typescript
const subtypeDepth = depth ?? 1;
const subtypes: HierarchyEntry[] = [];
let frontier = [item];
for (let d = 0; d < subtypeDepth && frontier.length > 0; d++) {
  const next: any[] = [];
  for (const f of frontier) {
    const subs = await endpoint.send('typeHierarchy/subtypes', { item: f });
    if (subs && subs.length > 0) {
      for (const s of subs) {
        subtypes.push(toHierarchyEntry(s, loadedProject, uriMapper));
        next.push(s);
      }
    }
  }
  frontier = next;
}
```

10. didClose (try/finally around all LSP calls after didOpen)

**`toHierarchyEntry` helper:**
```typescript
interface HierarchyEntry {
  name: string;         // Simple name
  qualifiedName: string; // FQN reconstructed from name + detail
  kind: string;          // SYMBOL_KIND_NAME mapped
  jar: string | null;    // jar ID or null for JDK types
  provenance: string;    // 'minecraft' | 'fabric-api' | 'library' | 'mod-source' | 'java'
}
```

For each TypeHierarchyItem:
- `qualifiedName`: if `detail` exists (package name), `${detail}.${name}`; otherwise just `name`
- Check URI scheme: if URI starts with `file://`, use `uriMapper.fromFileUri()` to get jar ID and look up provenance from `loadedProject.dependencyJars`. If URI starts with `jdt://` or any non-`file://` scheme, set `jar: null, provenance: 'java'`
- `kind`: `SYMBOL_KIND_NAME[item.kind] ?? 'unknown'`

**Return:**
```typescript
makeSuccess({
  class: className,
  jar: sourceJarId,
  extends: extendsChain,
  implements: implementsList,
  subtypes,
  subtypeDepth: subtypeDepth,
}, { provenance: { tool: 'type_hierarchy', project: loadedProject.name, class: className } })
```

**Text summary:** "Type hierarchy for {className}: extends {N} types, implements {M} interfaces, {K} direct subtype(s)"

**Important: TypeHierarchyItem.data is opaque -- never modify items returned by prepareTypeHierarchy before passing to supertypes/subtypes.**

**Step 1: Create `src/tools/search-symbols.ts`**

Implement `registerSearchSymbolsTool(server: McpServer)`:

**Input schema:**
- `query`: z.string() -- symbol name pattern to search
- `kind`: z.enum(['class', 'method', 'field', 'interface', 'enum', 'constructor', 'constant', 'property']).optional() -- filter by kind
- `limit`: z.number().int().min(1).max(200).default(50).optional()
- `offset`: z.number().int().min(0).default(0).optional()
- `project`: z.string().optional()

**Flow -- does NOT need didOpen/didClose (workspace/symbol searches entire workspace index):**
1. Resolve project, check JDT LS (standard boilerplate)
2. Check `endpoint` available: `if (!loadedProject.jdtls?.endpoint)` error
3. Call `endpoint.send('workspace/symbol', { query })` -- returns SymbolInformation[] or null
4. If null: return `makeSuccess({ results: [], total: 0, limit, offset })` with text "No symbols found"
5. If `kind` filter provided: map kind string to SymbolKind number using reverse lookup:
   ```typescript
   const KIND_NAME_TO_NUMBER: Record<string, number> = {
     'class': 5, 'method': 6, 'property': 7, 'field': 8,
     'constructor': 9, 'enum': 10, 'interface': 11,
     'constant': 14,
   };
   ```
   Filter results: `results.filter(s => s.kind === KIND_NAME_TO_NUMBER[kind])`
6. Paginate: `const total = filtered.length; const page = filtered.slice(offset, offset + limit);`
7. Transform each SymbolInformation to structured output:
   ```typescript
   {
     name: sym.name,
     kind: SYMBOL_KIND_NAME[sym.kind] ?? `unknown(${sym.kind})`,
     containerName: sym.containerName ?? null,
     deprecated: sym.tags?.includes(1) ?? false,
     location: {
       uri: sym.location.uri,
       jar: uriMapper.fromFileUri(sym.location.uri)?.jar ?? null,
       line: sym.location.range.start.line + 1,
       column: sym.location.range.start.character + 1,
     },
   }
   ```
   Use `createUriMapper(jdtls.tempDir, jdtls.jarIdToDirName)` for URI mapping.
8. Return `makeSuccess({ results: transformed, total, limit, offset }, { provenance })` with text "Found {total} symbols matching '{query}' (showing {offset+1}-{offset+page.length})"
