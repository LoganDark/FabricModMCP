<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user CLI → server | `--java-home` value flows in as untrusted (passed to `execFile` as a path arg) |
| gradle.properties → server | `org.gradle.java.home` value is untrusted file content; backslash escapes must be decoded safely |
| readdir(parent) → server | Filesystem enumeration of common install dirs returns untrusted entry names |
| execFile child process → server | Child stdout/stderr is untrusted text parsed by `parseJavaVersion` regex |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-01 | Tampering | `unescapePropertiesValue` consuming malicious `\uXXXX` sequences | mitigate | Single-pass scanner consumes exactly 4 hex digits; non-hex falls through to unknown-escape branch which drops the backslash; no eval/Function/regex compilation from input |
| T-37-02 | Injection | `execFile(resolved, ['--version'], ...)` with attacker-controlled candidate path from gradle.properties | mitigate | `execFile` takes file + args array (no shell), so spaces / quotes / metacharacters in path are passed literally; 3s timeout caps blast radius |
| T-37-03 | DoS | scan slot probing 50+ entries in `/opt` (postgres, intellij, etc.) | mitigate | D-16 entry-prefix filter restricts `/opt` to `(jdk-|.*-jdk|temurin-|zulu-|corretto-|openjdk-)`; D-15 short-circuits on first success |
| T-37-04 | Info disclosure | logger.debug emitting full file paths | accept | Local debug logs only; --verbose is opt-in; paths are not transmitted off-host |
| T-37-05 | DoS | readdir on a slow network mount in `commonJavaLocations()` | accept | The Phase 35 list contains only local-filesystem paths; mount latency is a deployment concern, not a code concern in v1.6 |
</threat_model>
