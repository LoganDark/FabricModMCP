## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → MCP server (`/add-study-jar`) | The PRIMARY attack vector this phase mitigates. User-supplied study jars are extracted to the JDT LS temp directory via `extractStudyJarToWorkspace` (Z1). A malicious jar contains entries with crafted paths (`..`, absolute paths, `\`-traversal) designed to escape the extraction root and write to arbitrary filesystem locations (ZIP-slip). |
| Loom/Maven → MCP server (source jars) | Lower-trust-but-not-adversarial. Same extraction path (Z2 in `syncFabricModToWorkspace`). The same WIN-07 traversal check applies — costs nothing in the common case (well-formed jars pass), defends against compromised upstreams. |
| MCP server → filesystem (`rm`, `mkdir`, `writeFile`) | The destination of the write. Without WIN-07, a malicious entry name like `'../../../../etc/passwd'` could cause `writeFile` to write outside `depDir`. With the post-resolution check, the boundary is enforced. |
| AV / Search Indexer → filesystem handles | The transient-failure surface. EBUSY/EPERM from external processes scanning files we just wrote causes `rm` to fail intermittently — WIN-06 mitigates with Node native retry. |
