<objective>
Investigate and fix why ../fabric-template mod's fabric.mod.json is not substituted properly when loaded by FabricModMCP.

**Root Cause (already diagnosed):** The fabric-template project uses Gradle `processResources` expansion in its fabric.mod.json -- fields like `"id": "${mod_id}"` are meant to be substituted at build time using values from gradle.properties. The `parseFabricMod` function reads the raw source file and returns literal `${mod_id}` as the mod ID, which then becomes the child name.

**Fix:** Apply the same `${property_name}` substitution that `parseBuildGradle` already does, but to the fabric.mod.json content before JSON parsing. The gradle properties are already available in the loader -- they just need to be threaded through to `parseFabricMod`.

Purpose: Mods using Gradle property expansion in fabric.mod.json (a standard Fabric Loom feature via `filesMatching`/`expand`) should load correctly.
Output: Updated fabric-mod.ts and loader.ts, with test coverage.
</objective>
