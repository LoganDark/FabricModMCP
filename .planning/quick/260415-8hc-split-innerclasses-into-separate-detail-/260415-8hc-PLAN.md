<objective>
Split the `innerClasses` detail from the `modifiers` flag in list_classes and search_classes.

Currently `details: { modifiers: true }` controls access, modifiers, AND innerClasses together. After this change:
- `details: { modifiers: true }` controls access/modifiers only
- `details: { innerClasses: true }` controls inner class listing
- When both are true, inner classes include their access/modifiers
- When only innerClasses is true, inner classes show name/fqn/kind only (compact)

Purpose: Gives Claude finer control over response verbosity -- inner class listings are often unnecessary when you just want to see if a class is abstract/final.
Output: Updated schema, strip function, descriptions, and tests.
</objective>
