<objective>
Fix a latent parser bug in `src/project/gradle-parser.ts` where two non-greedy regexes (`/repositories\s*\{([\s\S]*?)\n\}/` at line 50, `/dependencies\s*\{([\s\S]*?)\n\}/` at line 132) match the FIRST occurrence of the block name in a `build.gradle.kts` file. When the file contains a `buildscript { dependencies { classpath(...) } repositories { ... } }` wrapper (common in older Loom templates), the regex captures the buildscript's inner block instead of the top-level one, causing `parseBuildGradle` to throw `GRADLE_PARSE_MISSING_MINECRAFT` for real-world projects like `AuxCommands-1.21`.

Replace both regexes with a single `extractTopLevelBlock(content, name)` helper that tracks string state and brace depth to locate a `<name> { ... }` block at depth 0 and return its body, correctly handling nested `{ }` (e.g. a `for (...) { ... }` inside the dependencies block).

Purpose: Make the parser robust against `buildscript {}` wrappers and nested braces, so projects that follow common Loom conventions can be loaded without manually rewriting their build.gradle.kts.

Output: Updated `gradle-parser.ts` with the helper and two call-site swaps; new regression tests in `tests/project/gradle-parser.test.ts`.
</objective>

function stripLineComment(line: string): string {
	let inString = false;
	for (let i = 0; i < line.length; i++) {
		const c = line[i];
		if (c === '\\' && i + 1 < line.length) { i++; continue; }
		if (c === '"') { inString = !inString; continue; }
		if (!inString && c === '/' && line[i + 1] === '/') return line.slice(0, i);
	}
	return line;
}
