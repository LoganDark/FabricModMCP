<objective>
After 260428-59m, dep-source resolution looks at declared Maven roots and modules-2. But Loom remaps every Fabric mod dependency from intermediary into the project's mappings (yarn) and writes the result to `<projectRoot>/.gradle/loom-cache/remapped_mods/remapped/<group-as-path>/<artifact>-<hash>/<version>/`. The IDE displays yarn-mapped symbols, so the intermediary-mapped sources we currently return are silently wrong for the majority of Fabric mod deps (fabric-api, modmenu, auxcommands, etc.).

Probe the Loom remapped_mods cache FIRST, before declared Maven roots and modules-2. Apply the same probe to both sources and compiled jars (both are remapped). Extend the existing miss-warn to list the loom-cache root.

Purpose: dep-source mappings match what the user's IDE shows and what the project compiles against — symbol names align, JDT LS indexes the right sources, and `read_source` returns code the user can actually reference.

Output: A `resolveLoomRemappedJarPath` resolver in `loom-cache.ts`; `findSourcesJar` / `findCompiledJar` updated to probe it first; `dependency-discovery.ts` threading `projectRootPath` through the call chain; tests covering the new probe and ordering; verified end-to-end against the CreatorCore/Claude project.
</objective>

    ```ts
    export async function resolveLoomRemappedJarPath(
      projectRoot: string,
      group: string,
      artifact: string,
      version: string,
      filenameSuffix: '-sources.jar' | '.jar',
    ): Promise<string | null> {
      // <projectRoot>/.gradle/loom-cache/remapped_mods/remapped/<group-as-path>/
      const groupDir = join(
        projectRoot, '.gradle', 'loom-cache', 'remapped_mods', 'remapped',
        ...group.split('.'),
      );
      let entries: string[];
      try {
        entries = await readdir(groupDir);
      } catch {
        return null;
      }
      // Match `<artifact>-<hex>` (Loom hash). Bare `<artifact>` (no hash) does NOT match.
      const hashRegex = new RegExp(`^${artifact}-[a-f0-9]+$`);
      for (const dirName of entries) {
        if (!hashRegex.test(dirName)) continue;
        const versionDir = join(groupDir, dirName, version);
        const filename = `${dirName}-${version}${filenameSuffix}`;
        const candidate = join(versionDir, filename);
        try {
          await access(candidate);
          return candidate;
        } catch {
          continue;
        }
      }
      return null;
    }
    ```

    Use `escapeRegExp` if `artifact` could contain regex metacharacters — Maven artifact ids can contain `.` and `-`. Add a small inline `escapeRegex` helper or use a literal-safe approach (e.g., walk entries with `entry.startsWith(\`${artifact}-\`)` then verify the suffix is hex with a separate test). Choose whichever is cleaner; prefer the explicit `startsWith` + hex-suffix-check to avoid regex escaping concerns.
