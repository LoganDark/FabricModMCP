## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Comment-strip regex mangled `file://` URIs inside string literals**

- **Found during:** Task 1 (Task 1 GREEN debugging)
- **Issue:** The pre-existing `/\\/\\/.*$/gm` line-comment regex stripped `//abs/path/to/repo")` from `url = uri("file:///abs/path/to/repo")` because it sees the second/third slashes of `file:///` as a `//` line comment. With this bug present, the new `mavenRoots` extraction would always see `file:/` (truncated) and never match. None of the existing tests exercised string-literal URLs because the prior parser only cared about the `dependencies { ... }` block (Maven coords have no `//`).
- **Fix:** Replaced the blanket regex with `stripLineComment(line)` -- a per-line scanner that tracks double-quote state and only strips `//` when not inside a string literal. Handles `\"` escape sequences correctly.
- **Files modified:** `src/project/gradle-parser.ts`
- **Verification:** All 12 new mavenRoots tests pass; all existing 15 gradle-parser tests still pass; full 720-test suite green; `tsc --noEmit` clean.
- **Committed in:** `6cbc7e3` (Task 1 GREEN commit, alongside the feature implementation)
