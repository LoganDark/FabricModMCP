<objective>
Make FabricModMCP resolve dependency sources for artifacts published to user-declared `file://` Maven repositories (and `mavenLocal()`), not just `~/.gradle/caches/modules-2/files-2.1/`.

**Background:** Quick-260428-4zp diagnosed that `auxcommands` (in `/Users/LoganDark/Documents/Projects/CreatorCore/Claude`) is published to `~/maven` via `maven-publish` and consumed via a `maven { url = uri("file://${user.home}/maven") }` repo declaration. Gradle resolves it in place — it never lands in `modules-2` — so `findSourcesJar`'s hardcoded cache root misses, the catch silently returns `null`, and the dep is filtered out of every browsing tool. See `.planning/quick/260428-4zp-investigate-why-the-users-logandark-docu/260428-4zp-FINDINGS.md` for the full trace.

**Purpose:** Extend the project-config layer to extract `repositories { ... }` declarations and thread the resulting Maven roots into the three resolver functions (`findSourcesJar`, `findCompiledJar`, `findPomInModules2`) so locally-published artifacts resolve correctly. Add a load-time warn log naming any dep that fails resolution after probing all roots, so this class of bug is not silently invisible.

**Output:**
- `GradleConfig.mavenRoots: string[]` populated from `build.gradle.kts`
- Resolver functions probe declared roots (Maven layout) before falling back to `modules-2` (Gradle layout)
- Warn log on miss, naming coord + roots tried
- Tests covering the four supported repo-declaration syntaxes and the probe-order behaviour
</objective>

Standard Maven layout (the new probe — no sha1 directory):
`<root>/<group-with-dots-as-slashes>/<artifact>/<version>/<artifact>-<version>[-<classifier>].<ext>`

Example for `net.logandark:auxcommands:1.0.0+1.21.11` under `~/maven`:
`/Users/<u>/maven/net/logandark/auxcommands/1.0.0+1.21.11/auxcommands-1.0.0+1.21.11-sources.jar`

Modules-2 layout (existing, kept as fallback — sha1 directory level):
`<gradleCacheBase>/<group-with-dots>/<artifact>/<version>/<sha1>/<artifact>-<version>[-<classifier>].<ext>`

Note the group separator differs: Maven layout uses `/` (dots-to-slashes), modules-2 layout uses literal dots. Do NOT regress modules-2 behaviour.
