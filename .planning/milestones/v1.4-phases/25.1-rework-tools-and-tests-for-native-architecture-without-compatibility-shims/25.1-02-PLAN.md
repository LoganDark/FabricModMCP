**Create `src/tools/remove-project.ts`:**
- Tool name: `remove_project`
- Input schema: `{ project: z.string().describe('Name of the project to remove') }` — project is REQUIRED (not optional)
- Logic extracted from unload-project.ts full-project removal path (lines ~127-159):
  1. `const proj = projectStore.get(project)` — if not found, return error PROJECT_NOT_FOUND
  2. Close all jar handles: iterate `proj.children`, for each child call `jarReader.closeProject(proj.name)` (this handles all jars for the project). Actually check the existing unload-project.ts code for the exact cleanup sequence
  3. If `proj.jdtls`, call cleanup (shutdown, kill, rmdir) following the existing pattern
  4. `projectStore.delete(project)` — this now works for any project including 'default'
  5. Return success with `{ removed: project }`
- Import `jarReader` from `./shared-jar-reader.js`
- Import jdtls cleanup utilities as needed (check unload-project.ts imports)

**Create `src/tools/set-active-child.ts`:**
- Tool name: `set_active_child`
- Input schema: `{ project: PARAMS.project, child: z.string().describe('Name of the child to set as active') }`
- Logic:
  1. Resolve project via `resolveProjectSafely(project)`
  2. Check `loadedProject.children.has(child)` — if not found, return error CHILD_NOT_FOUND with tried=[child], suggestions=['Check available members with get_project_info']
  3. Check the child is a fabric mod (`child.kind === 'fabric-mod'`) — study jars can't be active children (they don't have namespaced deps). If not fabric-mod, return error INVALID_CHILD_TYPE with message 'Only fabric mods can be set as active child'
  4. Set `loadedProject.activeChild = child`
  5. Return success with `{ project: loadedProject.name, activeChild: child }`

**Create `src/tools/add-fabric-mod.ts`:**
- Tool name: `add_fabric_mod`
- Input schema: `{ project: PARAMS.project, path: z.string().describe('Absolute path to the Fabric mod root directory') }`
- Extract the "add child to existing project" code path from load-project.ts. Key logic:
  1. Resolve project via `resolveProjectSafely(project)`
  2. Call `loadFabricMod(path)` to parse gradle, discover sources jar, parse fabric.mod.json
  3. Derive child name from fabric.mod.json id
  4. Handle name collision: check `loadedProject.children.has(childName)`, if so auto-suffix with `-2`, `-3` etc. (copy the existing collision resolution logic from load-project.ts)
  5. Build FabricModChild: `{ kind: 'fabric-mod', name: childName, rootPath: path, gradleConfig, sourcesJar, fabricMod, dependencyJars, filterConfig: { mode: 'include-all', patterns: [] } }`
  6. Dependency discovery: call the same dependency resolution functions used in load-project.ts
  7. Register jars with `jarReader` — follow the exact jar registration pattern from load-project.ts
  8. Auto-unload conflicting study jars (same logic as load-project.ts)
  9. Add child to project: `loadedProject.children.set(childName, child)`
  10. JDT LS initialization if project has no existing session — follow load-project.ts pattern
  11. Return success with child summary (name, minecraftVersion, mappingEra, depCount)
- DO NOT import from compat.ts — all access is direct on the FabricModChild
- Import `loadFabricMod` from `../project/loader.js`
- Import jar registration utilities as used in load-project.ts

**Create `src/tools/remove-project-member.ts`:**
- Tool name: `remove_project_member`
- Input schema: `{ project: PARAMS.project, members: z.array(z.string()).min(1).describe('Names of members to remove') }`
- Logic combines unload-project.ts scoped path + remove-study-jar.ts:
  1. Resolve project via `resolveProjectSafely(project)`
  2. First pass: validate all names exist in `loadedProject.children` — fail on first missing name with CHILD_NOT_FOUND error, tried=[missingName], suggestions=['Check available members with get_project_info']
  3. Second pass: remove each member:
     - Get child from `loadedProject.children.get(name)`
     - If `child.kind === 'fabric-mod'`: close jars via `jarReader` (follow unload-project.ts scoped cleanup), remove JDT LS workspace entries if `loadedProject.jdtls` exists (follow unload-project.ts pattern for `.classpath` rebuild and JDT LS notification)
     - If `child.kind === 'study-jar'`: close jar via `jarReader.closeJar()` (follow remove-study-jar.ts pattern)
     - `loadedProject.children.delete(name)`
     - If `loadedProject.activeChild === name`, set `loadedProject.activeChild = undefined`
  4. Return success with `{ removed: string[], project: loadedProject.name }`
