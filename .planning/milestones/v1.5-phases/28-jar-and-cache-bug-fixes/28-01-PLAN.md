**FIX-01 — Cache eviction in remove_project (src/tools/remove-project.ts):**

Before the `await jarReader.closeProject(project)` call (line 52), add cache eviction logic. Follow the pattern from `remove-project-member.ts`:

1. Import `evictEntryIndex` from `'../browsing/entry-index-cache.js'`
2. Get jar paths: `const jarPaths = jarReader.getProjectJars(project)` — MUST be called before closeProject
3. If `jarPaths` exists, iterate and call `evictEntryIndex(jarPath)` for each
4. Also evict mod source cache keys: iterate `proj.children`, for each `fabric-mod` child, evict `fs:{child.rootPath}:{depId}` for each depId in `child.dependencyJars.keys()`, and also evict the minecraft sources jar path (`child.sourcesJar.path` if it exists). For `study-jar` children, the jar path is already covered by jarPaths iteration.

**FIX-03 — Race condition in JarReader.getHandle (src/project/jar-reader.ts):**

Change the `handles` map type from `Map<string, StreamZip.StreamZipAsync>` to `Map<string, Promise<StreamZip.StreamZipAsync>>`.

In `getHandle()`:
1. Check if map has entry — if so, `return this.handles.get(jarPath)!` (returns the Promise)
2. Create a promise and store it in the map IMMEDIATELY (before any await):
   ```
   const handlePromise = (async () => {
     const zip = new StreamZip.async({ file: jarPath, storeEntries: true });
     await zip.entries(); // validates
     return zip;
   })();
   this.handles.set(jarPath, handlePromise);
   ```
3. Wrap in try/catch: on failure, `this.handles.delete(jarPath)` then rethrow as DomainError
4. Use `try { return await handlePromise; } catch { this.handles.delete(jarPath); throw new DomainError(...); }`

Update `readEntry`, `listEntries`, `close`, `closeAll`, `closeProject`, and `removeProjectJar` to await the Promise from the map. For `close`: `const handlePromise = this.handles.get(jarPath); if (handlePromise) { const handle = await handlePromise; await handle.close(); this.handles.delete(jarPath); }`

Update tests to cover concurrent access and failure retry.
