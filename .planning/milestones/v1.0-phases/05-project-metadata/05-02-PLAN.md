```typescript
import { z } from 'zod';
import { stat } from 'node:fs/promises';
import type { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';

```

The tool name is `get_project_metadata`. Input schema has these Zod fields:
- `project: z.string().optional()` -- Project name (optional)
- `include_project_info: z.boolean().optional()` -- Include version/mappings info
- `include_mod_info: z.boolean().optional()` -- Include fabric.mod.json metadata
- `include_jar_inventory: z.boolean().optional()` -- Include all source jar entries
- `include_paths: z.boolean().optional()` -- Include file system paths for jars (debug)

Default behavior: When NO category flags are specified (all undefined/false), include ALL categories. When ANY flag is explicitly true, include only flagged categories.

Implement three builder functions:

`buildProjectInfo(project: LoadedProject)` returns:
```typescript
{
	minecraftVersion: gc.minecraftVersion,
	mappingEra: gc.mappingEra,
	yarnMappings: gc.yarnMappings ?? null,
	loaderVersion: gc.loaderVersion ?? null,
	fabricApiVersion: gc.fabricApiVersion ?? null,
}
```

`buildModInfo(project: LoadedProject)` returns:
- Destructure `project.fabricMod` as `Record<string, unknown>` to capture passthrough extra keys
- Extract known fields: `schemaVersion, id, version, name, description, authors, license, environment, mixins, depends`
- Collect remaining keys into `extra` via spread
- Return object with all known fields plus `extra: Object.keys(extra).length > 0 ? extra : undefined`

`async buildJarInventory(project: LoadedProject, includePaths: boolean)` returns array:
- Iterate `project.dependencyJars` entries
- For each entry, if `available && sourcesJarPath`, try `stat(sourcesJarPath)` for `sizeBytes` (catch to null)
- If not available or no sourcesJarPath, `sizeBytes = null`
- Build entry object with: `id, category, group, artifact, version, available, sizeBytes, provenanceChains`
- If `includePaths && dep.sourcesJarPath`, add `sourcesJarPath` to the entry
- Return array of all entries

Handler logic:
- Resolve project via `projectStore.resolveProject(project)` with standard DomainError catch
- Determine if any category flag is explicitly true: `const anyExplicit = include_project_info || include_mod_info || include_jar_inventory`
- If `!anyExplicit`, include all. Otherwise include only flagged categories.
- Build response data object with optional keys: `projectInfo`, `modInfo`, `jarInventory` (only present if category is included)
- Wrap in `makeSuccess(data, { provenance: { tool: 'get_project_metadata', project: loadedProject.name } })`
- Return both `content` (text JSON) and `structuredContent` per established pattern

Export: `registerGetProjectMetadataTool(server: McpServer): void`
