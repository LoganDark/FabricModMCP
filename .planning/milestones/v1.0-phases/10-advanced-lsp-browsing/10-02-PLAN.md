**Step 1: Create `src/tools/resolve-symbol-position.ts`**

Extract the cascading-regex-to-position pattern shared by find_definition, find_references, and now get_symbol_info/find_implementations. This is NOT "DRY refactoring" of existing tools (deferred) -- this is creating a shared helper for the two new tools to avoid quadruple duplication.

```typescript
import type { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import type { DependencyEntry, JarCategory } from '../project/types.js';
import type { LoadedProject } from '../project/types.js';
import type { CascadeStep, CascadeSuccess } from '../browsing/cascading-regex.js';
import { getFilteredDependencies } from '../project/jar-registry.js';
import { jarReader } from './shared-jar-reader.js';
import { createSourceAdapter } from '../browsing/source-adapter.js';
import { cascadeRegex } from '../browsing/cascading-regex.js';
import { createUriMapper } from '../jdtls/uri-mapper.js';

// Priority order for jar categories when searching all jars
const CATEGORY_PRIORITY: Record<JarCategory, number> = {
  'minecraft': 0,
  'mod-source': 1,
  'fabric-api': 2,
  'library': 3,
};

export interface SymbolPositionSuccess {
  success: true;
  sourceJarId: string;
  sourceText: string;
  cascadeResult: CascadeSuccess;
  fileUri: string;
  entryPath: string;
}

export interface SymbolPositionCascadeFailure {
  success: false;
  kind: 'cascade-failure';
  jar: string;
  category: JarCategory;
  provenanceChains: string[][];
  steps: CascadeStep[];
  failedStep: number;
  error?: string;
}

export interface SymbolPositionNotFound {
  success: false;
  kind: 'not-found';
  entryPath: string;
}

export interface SymbolPositionJarError {
  success: false;
  kind: 'jar-not-found' | 'jar-not-available';
  jar: string;
}

export type SymbolPositionResult = SymbolPositionSuccess | SymbolPositionCascadeFailure | SymbolPositionNotFound | SymbolPositionJarError;
```

The function `resolveSymbolPosition(loadedProject, className, patterns, jar?)` should:
1. Convert FQN to entry path (same as find_definition)
2. Create uriMapper from jdtls session
3. If jar specified: read source, cascade, return success or failure
4. If no jar: iterate filtered deps by priority, find first cascade match
5. On success: return `{ success: true, sourceJarId, sourceText, cascadeResult, fileUri, entryPath }`
6. On cascade failure: return `{ success: false, kind: 'cascade-failure', ... }`
7. On class not found: return `{ success: false, kind: 'not-found', entryPath }`

**Step 2: Create `src/tools/get-symbol-info.ts`**

Implement `registerGetSymbolInfoTool(server: McpServer)`:

**Input schema:**
- `class`: z.string() -- FQN
- `patterns`: z.array(z.string()).min(1) -- cascading regex patterns
- `jar`: z.string().optional()
- `project`: z.string().optional()

**Flow:**
1. Resolve project, check JDT LS (same boilerplate as find_definition)
2. Call `resolveSymbolPosition(loadedProject, className, patterns, jar)` 
3. If not success, return appropriate error envelope
4. didOpen with sourceText
5. Call `lspClient.hover({ textDocument: { uri: fileUri }, position: { line: cascadeResult.line - 1, character: cascadeResult.column - 1 } })`
6. didClose (try/finally)
7. Process hover result:
   - If null/undefined: return `makeSuccess({ hover: null, javadoc: '', position: ... })` with text "No hover info available"
   - Extract markdown from `result.contents`:
     - If MarkupContent (has `kind` and `value`): use `value`
     - If string: use directly
     - If MarkedString[] (array): join with '\n\n'
   - **Filter import/package declarations:** If the hover markdown matches `/^(import|package)\s/`, return `makeSuccess({ hover: null, javadoc: '', position: ... })` with text "Position is on an import/package declaration -- no useful symbol info"
   - Otherwise return `makeSuccess({ hover: hoverMarkdown, javadoc: '', position: { jar, class, line, column } })` 
   - Always include `javadoc: ''` field (per CONTEXT.md: decompiled source rarely has full docs, always include field even when empty)
